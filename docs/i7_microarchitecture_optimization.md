# Микроархитектурная оптимизация VCPU под Intel Core i7 (SPIN State-Space Exploration)

Данный документ описывает формальную модель взаимодействия многоядерного VCPU-рантайма с микроархитектурой современных процессоров **Intel Core i7** (архитектуры Raptor Lake / Alder Lake / Arrow Lake с 8 Performance-ядрами), реализованную в [`models/i7_multicore_vcpu_optimizer.pml`](../models/i7_multicore_vcpu_optimizer.pml).

---

## 1. Аппаратная модель задержек Intel Core i7

Многоядерный защитный рантайм распределяет выполнение виртуального байткода между $N$ независимыми VCPU-ядрами, взаимодействующими через разделяемую память кэша L3 и синхронизированные почтовые ящики.

### Аппаратные характеристики (Intel ARK Specification — Core i7-14700K):
* **Архитектура:** Raptor Lake Refresh (8 P-Cores + 12 E-Cores, 28 Threads).
* **L1 Data Cache:** 48 KB на ядро (L1d Latency $\approx 4$–$5$ тактов).
* **L2 Cache:** 2.0 MB на P-core (суммарно 28 MB L2, Latency $\approx 14$ тактов).
* **L3 Smart Cache (LLC):** 33 MB (Shared Ring Bus, Latency $\approx 45$ тактов на MESI invalidation).
* **Штраф планировщика ОС (Context Switch Penalty):** Наступает при $N > 8$ (когда число активных VCPU превышает 8 Performance-ядер), добавляя $\approx 1500$–$2500$ тактов на переключение потока ОС и вызывая сброс L1/L2 кэшей.

Формула суммарных аппаратных затрат:
$$T_{\mathrm{exec}}(N) = \left[ N \cdot T_{\mathrm{L1}} + (N - 1) \cdot T_{\mathrm{MESI}} \right] \times \left(1 + 0.04 \cdot N^{1.4}\right) + P_{\mathrm{switch}}$$

## 2. Модель сложности для девиртуализатора (Z3 / VTIL SMT)

Для статического аналитика и декомпилятора сложность восстановления плоского графа потока управления (CFG) и снятия SSA-формы растёт экспоненциально:
1. **Факториальный взрыв перестановок состояний:** $N!$ независимых матриц перестановок регистров.
2. **Символьное ветвление путей (Path Explosion):** $2^{1.5 \cdot N}$ возможных путей в дереве SMT-запросов.
3. **Нелинейные перекрёстные члены (AST Complexity):** $N^3$ перекрёстных алгебраических связей.

Суммарная сложность анализа:
$$\text{Complexity}(N) \approx N! \times 2^{1.5 \cdot N} \times N^3$$

## 4. Практические рекомендации по развёртыванию

```text
  Защита
   100% |                                  *====*====*  [Зона избыточности / троттлинга]
        |                             *
        |                        *           <- N = 8: Максимальный щит (602 такта)
        |                   *
    50% |              *                     <- N = 4: Быстрый рубеж (193 такта)
        |         *
        |    *
     0% |*
        +------------------------------------------------------------> Такты i7
        0     100    200    300    400    500    600   >3000
```

1. **$N = 4$ VCPU (Fast-Path профиль):**
   * Задержка: **193 такта** (быстрее одного случайного чтения из оперативной памяти DRAM $\approx 200$ тактов).
   * Применение: функции рендеринга, обработка физики, сетевые пакеты, частые вызовы в цикле.
   * Уровень стойкости: разрушает алгоритмы `stack_pinning_pass` и `bblock_extension_pass` в VTIL.

2. **$N = 6 \dots 8$ VCPU (Max Fortress профиль):**
   * Задержка: **371–602 такта**.
   * Применение: проверка лицензий, запуск защищённого модуля, DRM-ключи, анти-чит хуки.
   * Уровень стойкости: экспоненциальный взрыв $10^{8} \dots 10^{11}$ состояний. SMT-солвер Z3 аварийно завершает работу по таймауту или нехватке памяти.

3. **$N > 8$ VCPU (Penalty Wall):**
   * Превышение физического числа Performance-ядер i7 приводит к деградации производительности на $500\% \dots 1700\%$ из-за переключения контекста потоков ОС, не давая практического прироста безопасности (солвер и так гарантированно ломается при $N=8$).
