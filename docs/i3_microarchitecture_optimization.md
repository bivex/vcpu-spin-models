# Микроархитектурная оптимизация VCPU под Intel Core i3 (SPIN State-Space Exploration)

Данный документ описывает формальную модель многоядерного VCPU-рантайма на 4-ядерных бюджетных и энергоэффективных процессорах **Intel Core i3** (архитектуры Alder Lake / Raptor Lake: i3-12100, i3-13100, i3-14100), реализованную в [`models/i3_multicore_vcpu_optimizer.pml`](../models/i3_multicore_vcpu_optimizer.pml).

---

## 1. Специфика микроархитектуры Intel Core i3

В отличие от 8-ядерных Core i7, процессоры линейки Core i3 имеют критические аппаратные ограничения:
1. **Топология ядер:** Всего **4 физических ядра** (4 Cores / 8 Threads).
2. **Кэш L3 (LLC):** Урезанный объём ($\approx 12$ МБ против $24$–$36$ МБ у i7), что увеличивает вероятность конкуренции за кэш-линии (Cache Contention Factor $\approx 0.08$).
3. **Критический порог переключения контекста:** Наступает уже при **$N > 4$ VCPU** (вместо $N > 8$ у i7). При $N \ge 5$ потоки начинают вытеснять друг друга, приводя к принудительным переключениям контекста ОС ($\approx 1800$ тактов на переключение).

## 4. Практические рекомендации для Intel Core i3:

1. **Строго $N = 3 \dots 4$ VCPU для Core i3:**
   * **$N = 4$ VCPU** является абсолютным технологическим максимумом для систем с Core i3:
     * Задержка: **235 тактов** (позволяет выполнять в реальном времени до $10^6$ вызовов защищённых функций в секунду).
     * Сложность девиртуализации: $\approx 10^5$ перестановок графа (полностью ломает `stack_pinning_pass` и линейный SSA-дизассемблер VTIL).
2. **Категорический запрет $N \ge 5$ на 4-ядерных CPU:**
   * Переход с $N=4$ на $N=5$ на процессоре i3 вызывает скачок задержки с **235 до 2152 тактов** ($+915\%$) из-за необходимости ОС непрерывно квантовать время между 5 потоками на 4 физических ядрах.
